### Current verified architecture

Conceptual, privacy-safe structure verified in the current repository
(`README.md`, `docs/agent-gateway/01-architecture.md`):

```text
Platform934 clients
        |
        v
Platform934 API (single authenticated .NET API project with internal
  Features / Infrastructure / Shared.Contracts boundaries)
        |
        +--> Typed Jellyfin client --> official Jellyfin API
        +--> Semantic Kernel + allowlisted plugins --> LiteLLM
        |                                                |
        |                                        configured provider routes
        +--> PostgreSQL (EF Core)
        +--> SignalR device hub --> first-party active devices
```

- LLM access goes through the agent layer, never directly from the API layer.
- Jellyfin access goes through the typed Jellyfin client boundary, never directly
  from agent plugins.
- Tools are allowlisted and typed; application services remain authoritative for
  catalogue facts, identifiers, recommendations, actions and playback safety.
- Provider ordering and fallback live inside LiteLLM; the application selects
  logical routes only.

This is a conceptual diagram. It does not expose deployment topology, endpoints,
credentials, provider secrets or source. It also does not claim that every
ordinary client request routes through the API.
